## Blocking Current Release Packaging

- The local Keychain reports zero valid code-signing identities.
- GitHub has no configured repository signing secrets, and Actions is disabled.
- Both existing packaging scripts fail their required persistent-signing
  preflight before creating/replacing a release bundle. This expected rejection
  is not counted as a successful signed-package build.
- Developer ID signing/notarization has not been performed. No certificate,
  Keychain trust, credentials, repository setting or signing guard was changed.

The current project policy requires a persistent identity for final releases.
Publishing ad-hoc packages instead would be an explicit distribution-policy
decision with permission-continuity and Gatekeeper caveats, not an unnoticed
fallback or a claim of notarization.
