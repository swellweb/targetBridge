# TargetBridge 3.6.1-rc.2

Maintenance prerelease for testing, not stable 3.6.1. Keep installed 3.6.0
apps and preferences; use separate test copies.

## Changes

- Improve Simplified Chinese wording in Sender and Receiver (#212).
- Follow the supported macOS language order on first launch, while preserving
  an explicitly saved language; fall back to English if necessary (#213).
- Centre the Receiver connecting-screen text and translate its role label in
  all five supported languages (#214).
- Correct the Receiver waiting-screen layout orientation (#215), and scale
  the idle dashboard to keep cards and help text separate in smaller windows.
- Exclude development-only scripts from the Sender app bundle while keeping
  language and addon resources (#216).
- Keep Sender and Receiver version stamps aligned, with regression coverage
  for the Sender's footer and bundle version.
- Restore Full HD labels and complete Italian UI translations (#220).
- Preserve active status when the first frame arrives early (#222).
- Persist and correctly apply the menu-bar icon preference (#224).
- Present the newest decoded frame under backlog, with cooperative parser
  yielding that preserves encoded packets and handles teardown (#230).
- Space keyframes and cap peak rate for the existing experimental 5K60
  profile (#231). Sustained 5K60 is not guaranteed.
- Advertise hardware and software HEVC capabilities separately; require
  explicit software support and handle key-only Bonjour TXT safely (#232).

## Validation And Remaining Checks

The following results describe the earlier maintenance baseline, not the exact
rc.2 source. Fresh results are recorded in
[3.6.1-rc.2 validation](3.6.1-rc.2-validation.md).

- 181 Sender unit tests on Apple Silicon, including saved-language and footer
  version regression tests; Release compilation for arm64 and x86_64.
- 697 Receiver checks on both Apple Silicon and the Intel iMac, including
  small-window geometry coverage from 640 x 480 through 5K.
- Five-language resource validation, offscreen waiting/connecting previews,
  and the local mock-sender handshake, corrupt-packet, watchdog and H.264
  decode/render smoke test.
- Signed development app packages for the arm64 Sender and both Receiver
  architectures. The Sender bundle keeps all five language JSON files and
  all three addon manifests, without the localization-check shell script.

The isolated idle-display-sleep test for #132 remains inconclusive because an
already-running Sender connected during the initial check. This issue is not
being marked fixed by the candidate. These are local checks, not a successful
hosted CI run. Workflow definitions are active; current-candidate hosted CI
must be checked separately.

Before publication, validate the final packaged apps on both supported
architectures and run a real two-Mac Thunderbolt session covering video,
audio relay, input roles, native cursor shapes, reconnect and display scaling.
Local loopback tests are not a substitute for that hardware check.

Both packaged architectures require macOS 14 or later. Packages are ad-hoc
signed development builds, not notarized or signed with a persistent release
identity. Permission continuity is not certified; do not replace a persistently
signed installation. Sleep/wake, physical cable interruption, long stress,
audible audio, exact input/cursor behavior and software-only HEVC throughput
remain unverified. The parser budget is cooperative, not hard preemption.

No #221 window-lifecycle change, Retina 16:10, RGB10, DPCM, 4.0, new audio
controls, native Metal renderer or older-macOS support is included.
