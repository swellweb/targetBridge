# TargetBridge 4.0

TargetBridge 4.0 adds uncompressed video modes that send only what changes on
screen, optionally in 10-bit colour over parallel connections, with one-click
5K stream profiles for them. It also adds a per-session audio output device, a
version check between Sender and Receiver, and a quieter, more configurable
Receiver.

> The version number is this fork's proposal. Whether these changes ship as
> 4.0 upstream is up to the original maintainer.

## Highlights

### Uncompressed video

The video compression setting now offers four uncompressed options next to
Automatic, H.264 and HEVC. All of them skip the video codec, so the picture
arrives without compression artefacts, and all of them send only the rows of
the screen that changed: a still desktop costs almost no bandwidth.

| Option | Captured | Sent and shown | Frame rate at 5K |
|---|---|---|---|
| Uncompressed (8-bit) | 8-bit 4:2:0 | 8-bit 4:2:0 | 60 Hz |
| Uncompressed, LZ4, lossless (8-bit) | 8-bit 4:2:0 | 8-bit 4:2:0, compressed losslessly | 60 Hz |
| Uncompressed, enhanced (10-bit dithered, experimental) | 10-bit | 8-bit 4:2:0 with dithering | 60 Hz |
| Uncompressed, full colour (10-bit, experimental) | 10-bit | 10-bit RGB 4:4:4 | about 30 fps for video and scrolling |

- **Changed rows only.** The Sender reads ScreenCaptureKit's dirty rectangles
  and sends only the affected rows. Rows from frames skipped by the frame-rate
  limit or a busy link are kept and sent with the next frame. The first frame,
  size changes and one frame every 5 seconds are sent in full.
- **Lossless LZ4.** Changed rows are compressed in parallel chunks on the
  Sender and decompressed in parallel on the Receiver. The picture stays
  bit-identical.
- **10-bit dithered.** Captured in 10-bit, displayed in 8-bit: a GPU shader
  converts only the rows to send to 8-bit 4:2:0 with a fixed dither pattern, so
  gradients stay smooth at the 8-bit bandwidth.
- **Full 10-bit colour.** The captured 10-bit pixels are sent unchanged at
  4 bytes per pixel and full colour resolution. Whether the iMac shows true
  10-bit depends on its renderer; the Receiver's stats overlay shows it.
- **Parallel data streams.** Both 10-bit modes open up to 4 extra connections
  and spread each frame across them. The Receiver keeps rows in the right order
  even when parts arrive out of order.
- **Faster drawing.** The Receiver uploads only the changed rows to the
  graphics card.

- **One-click 5K profiles.** Four stream profiles pick both 5K at 60 Hz and the
  matching mode: *5K 60 Uncompressed (8-bit)*, *5K 60 LZ4, lossless (8-bit)*,
  *5K 60 10-bit dithered* and *5K 60 Full 10-bit*. While one of them is
  selected, the video compression setting shows the mode and is locked.
  Automation accepts them as `5k60raw`, `5k60lz4`, `5k60dither` and
  `5k60full10`.

Each new capability falls back on its own: an older Receiver gets full frames,
a Receiver without LZ4 gets uncompressed rows, and without a usable GPU or
10-bit support the Sender uses the next simpler mode. See
[Performance](../Performance.md) for details and the wire format.

### Version check

Sender and Receiver now tell each other their version. If they differ, the
Sender shows a notice with a **Download update** button, and the Receiver shows
it at the bottom of the picture for 20 seconds and in its menu bar, with a
download item, until the session ends. Both name the app that should be
updated. A Receiver older than 4.0 doesn't report a version and is treated as
older.

### Audio

- **TargetBridge Audio output device.** Select it as a per-session audio
  source; it only appears in macOS while a session is running.
- The Mac's volume for this device drives the iMac's speaker volume, and the
  iMac returns to its previous volume when a session ends.
- Per-session automatic audio output selection, returning to the previous
  output after a session, with the built-in output as fallback.
- The audio device can be renamed in Settings > Audio. If the driver needs a
  restart, the Sender shows the `sudo killall coreaudiod` hint.

### Receiver

- **Background mode** with a menu bar icon, and an option to show the window
  at start.
- New bottom bar with the Receiver's checkboxes beside the version and the
  Login Items hint; the upside-down waiting screen is fixed.
- **Performance** submenu: draw only the newest frame, wake on incoming data,
  Metal renderer, and a stats overlay with frame rate, skipped frames, draw
  time, data rate and the share of changed rows.

### Sender

- Default language follows the system, with an English fallback.
- Session names are editable, sessions can connect automatically, and session
  settings open in a regular window.
- The macOS display is named after the session.
- Brightness Keys and Audio Device add-ons.

## Upgrade

Update both Sender and Receiver to 4.0. The new uncompressed modes need the
4.0 Receiver; with an older Receiver the Sender falls back to full raw frames
or to Automatic. All protocol additions are optional fields and new packet
types, so 3.x Receivers keep working with the established codec modes.

For comparisons on real hardware, start the Sender with `RAW_REGIONS=0` to
send full frames again in the uncompressed modes.

### Keeping privacy permissions across updates

macOS ties Screen Recording, Accessibility and Input Monitoring to the app's
code signature. The builds are signed ad-hoc, which gives every build a new
identity, so macOS asks again after each update. The new
[`scripts/sign-local.sh`](../../scripts/sign-local.sh) signs the installed
apps with your own certificate; run it after each update, before the first
launch. After one last approval, later updates keep the permissions. See
[Sender signing](../Sender-Signing.md#keep-permissions-on-your-own-macs-sign-after-installing)
for setting up the certificate once.

## Validation

CI builds the Sender and Receiver for Apple Silicon and Intel and runs the
Sender unit tests and the Receiver parser, input-queue, watchdog, profile,
raw-region and version tests, including out-of-order parts and malformed
packets. The 8-bit
uncompressed modes have been tested on a real Mac-to-iMac Thunderbolt setup.
The two 10-bit modes are new and still need that hardware test.

## Known Limitations

- ScreenCaptureKit does not document whether dirty rectangles are in points or
  pixels. Ambiguous rectangles are sent in both readings, which can cost some
  extra bandwidth; any stale area is repaired by the full frame every
  5 seconds.
- Full 10-bit colour shows 8 bits if the Receiver's renderer cannot keep
  10-bit textures; colour resolution stays 4:4:4.
- Aligning frames with the iMac's refresh (vsync) is not implemented yet.
- Uncompressed modes are not available for headless mirror sessions, which
  capture through a different path.
